# 架构设计

状态：本地第一版已实现并通过集成测试，真实课程与 Android 真机待验收。已确认需求见 REQUIREMENTS.md，运行限制见 RUNNING.md。

## 服务边界

```text
Android / 电脑浏览器
    │ HTTPS、个人账户会话
外网连接服务
    │ 转发到本地主机
Windows 应用服务（网页与 API 同源）
    ├─ 持久化任务队列 → 单 Agent 执行器 → DeepSeek API
    ├─ 受控工具 → 本地资料、全文索引、历史、记忆
    └─ 后台资料扫描与解析 → 发布新索引版本
```

浏览器不直连数据库或 DeepSeek。网页连接断开不影响执行器。索引后台工作不属于第二个 Agent，但必须与读取和记忆写入协调版本。

## 建议技术组成

- Python / FastAPI 服务负责文件解析、任务调度、模型工具循环和 HTTP API；当前验证版本记录在 requirements.lock.txt。
- SQLite 保存聊天、任务、文件版本、来源证据和修订；FTS5 用于全文搜索。
- 中文不能仅依赖默认按空白分词：建立中文分词与英文术语索引，配合短语检索、同义词扩展与无结果降级。检索策略需用中文课程样本验证。
- 前端使用适配手机的网页，Markdown 和公式渲染输出必须经过安全处理。第一版通过定期查询任务状态恢复连接，不依赖流式输出或 SSE。
- PWA 缓存界面资源即可，不默认缓存原件、密钥或敏感聊天；离线界面明确表示无法请求主机。

## 本地数据布局建议

```text
data/
  knowledge/               # 资料原件，Agent 只读
  generated/               # 用户要求保存的总结和练习
  memory/
    profile/
    learning/
    understanding/
  app.sqlite3              # 索引、会话、任务、证据、修订
  staging/                 # 上传和解析暂存，不参与检索
  backups/                 # 用户发起的备份
```

资料根目录可配置；Agent 工具接收内部文档 ID，不接收任意系统路径。校验路径边界和链接，禁止通过上传路径越界。

## 数据与任务一致性

1. 用户消息与待执行任务先持久化，再返回已排队；客户端请求标识避免断线重试重复提交。
2. 执行器全局串行取任务，记录状态：排队、生成中、检索中、读取中、更新记忆、完成、失败、中断。
3. 模型提出工具调用；程序校验参数、范围、预算和版本，再执行并返回结果。
4. 模型输出最终回答后，程序核对引用属于已读取证据且版本适用；核验失败则不发布该回答，提示用户重查。当前没有实现模型语义审核或自动引用修复，不能保证每个结论都正确。
5. 最终回答与任务完成状态一致保存，客户端按任务 ID 获取，不依赖长连接存活。
6. 服务启动时将遗留运行任务标记中断，保留未执行队列；写入中断通过修订状态核对，不盲目重复。

## 索引与来源版本

扫描发现变化后，对稳定文件计算指纹，按页/幻灯片/段落提取；解析成功后原子发布新版本。解析期间再次发生变化则丢弃过期结果并重排。

保存文档 ID、相对路径、指纹、版本、位置、片段文本、解析警告与索引状态。删除原件立即使当前检索记录不可用；相关理解标记待复核。

读取和最终引用检查版本。旧回答保留当时引用片段与版本；原件变化后提示已变化，不用新页冒充旧页。第一版不承诺完整原件版本归档。

## Markdown 记忆

每轮成功回答与 `memory_status=pending` 一起保存。依用户后续选择，改为聊天闲置后批量判断：默认 120 秒无活动且全局没有排队任务时，现有单 Agent 执行器取同一聊天最多 20 轮，额外请求一次已配置模型，判断个人背景、偏好、目标和学习反馈。没有新增或纠正则不写 Markdown。不是每轮固定增加一次请求，也不创建第二个 Agent。

模型获得该批用户消息、回答、最多 10 条此前角色明确的历史和现有记忆，输出带主题键、事实类别、陈述及用户原话的结构化候选。程序校验用户原话属于待整理批次，写入 `profile/自动记忆.md` 或 `learning/自动记忆.md`，相同主题替换、其他主题保留；语义去重和真实性判断仍依赖模型。助手推测显式标注，讲解过或未追问不能作为掌握依据。资料理解继续走带已读来源的 remember 工具。

整理期间新消息到达则丢弃本次候选，延后再整理。请求限 45 秒，过大上下文（10 万字符以上）跳过且记录状态，不静默截断已有记忆去重依据。整理失败不改变已完成回答；整理中的重启标为中断，不自动重放不确定写入。任务的 `memory_status` / `memory_error` 可从聊天 API 检查。后续回答按相关度和个人记忆优先级加载记忆，仍可通过 memories 工具继续查阅。

记忆文件在数据库中关联稳定 ID、类型、来源版本和更新时间，Markdown 正文由模型写明依据。写入前比较读取时的内容哈希；第一版按整文件保护手工修改，条目级合并后续增强。

修订保存前后文本及预期哈希；原子替换文件与数据库修订采用可恢复状态记录，启动后核对。撤销只在当前内容仍匹配该修订且没有后续冲突时执行。

## 访问与配置

单账户密码哈希存储；服务端会话、HTTPS 安全 Cookie、登录限速与写操作来源检查。资料、来源下载和记忆接口均校验登录，不仅保护网页入口。

模型地址、模型名、密钥、资料目录和任务上限为配置项。日志不记录密钥或完整模型请求。工具结果中的文档内容始终按不可信数据处理。

公网方案以隧道为候选，先验证可达性再选择固定域名。Sites 域名不等同于本机入口，本项目不绑定 ChatGPT 登录。

早期聊天以保留 role 字段的结构化上下文数据交给模型；只在当前工具调用循环中临时保留 API 要求的 reasoning_content，不保存或展示内部推理。旧聊天仍可按原发言角色检索。
