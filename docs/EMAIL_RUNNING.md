# 邮件功能运行与验收

2026-11-02：本地实现已完成，使用模拟邮箱、模型及 SMTP 验证。尚未配置真实学生邮箱凭证，未连接真实邮箱、未发送真实邮件。真实账户的服务开通、文件夹和发送副本行为仍待验证。需求依据为 [EMAIL_REQUIREMENTS.md](EMAIL_REQUIREMENTS.md)。待办提醒保持暂停；没有创建额外定时或持续自动任务。

## 在 Windows 主机配置

1. 在原 Hikari 启动窗口停止服务，保留现有 `data` 目录。不要在聊天里发送邮箱密码。
2. 在项目目录的主机终端运行：

   ```powershell
   .\.venv\Scripts\python.exe -m hikari email-setup
   ```

3. 按提示输入完整 `@smail.nju.edu.cn` 地址和邮箱客户端专用密码。密码通过隐藏输入读取，以 Windows DPAPI 加密保存为数据目录中的 `email-secret.dpapi`，绑定当前 Windows 用户。没有明文回退，不通过网页配置、返回或发送给模型。主机终端配置完成后，重新启动 Hikari。
4. 已发送文件夹留空时，程序尝试从 IMAP `\Sent` 标记发现。服务器未提供该标记时，同步会提示配置问题，需要停服后重新运行配置命令并指定服务器实际的 IMAP 文件夹名。不要猜测中文文件夹的编码；可在客户端配置资料或服务器文件夹列表中核实。
5. 登录现有网页，打开“邮件”。正常情况下约两分钟同步一次，主机休眠、关机或 Hikari 停止时不运行。网络失败从两分钟开始退避，最多三十分钟；认证失败后停止尝试，重新配置并重启后恢复。

官方 [学生邮箱客户端配置办法](https://itsc.nju.edu.cn/_s302/1a/8f/c21586a334479/page.psp) 于本次实施时核对：IMAP 为 `imap.exmail.qq.com:993`，SMTP 为 `smtp.exmail.qq.com:465`，均为 SSL。需要在邮箱网页启用客户端服务，账户情况以实际登录为准。适配器固定使用这两个主机和正常证书校验，不允许邮件内容或模型修改连接参数。

尚无凭证时可以启动服务、查看邮件页面、编辑独立邮件资料、运行全部模拟测试。不要把模拟通过当成真实邮箱已经连通。

## 同步、背景与资料范围

- 启用时间持久保存；首次收取近 366 天的收件与已发送背景，仅对启用后收到的新邮件自动分类拟稿。恢复后补取遗漏，不将历史背景批量拟稿。旧邮件可主动请求拟稿。
- IMAP 使用只读选择和 `BODY.PEEK`，不标为已读，不移动、删除邮件，不写服务器草稿或已发送文件夹。
- 用 RFC Message-ID 去重，没有该字段时用原始邮件的 SHA-256 标识；UID/UIDVALIDITY 只用作位置。常规同步不重新下载已经清理的正文。UID 变化时先检查邮件头，再用持久标识识别；无法可靠匹配的情况保留本地记录，不推断远端删除。
- 优先使用 References / In-Reply-To 关联线程，发件人相同不会合并主题。可以提供同一发件人的其他往来作为参考。没有有效线程头的邮件不能可靠识别为同一线程；需真实邮件样本验收。
- “补取更早的关联邮件”按明确的线程引用查找一年以前的邮件，每次最多 20 个引用。不是按姓名或主题猜测历史。草稿旁可展开实际提供给模型的参考邮件和标识。
- `data/email/profile.md` 为独立邮件个人资料；`rules.md` 为持久排除规则。网页修改和主机直接修改都会保留修订，冲突要求刷新。模型不自动改这两个文件。
- 不加载学习聊天的全量记忆。需要课程、记忆或个人安排时，由用户选择相关内容放入邮件个人资料，并写清哪些可参考、哪些允许对外披露。用户未提供的身份、时间与承诺应列为问题。
- 规则记录实际地址、`scope=sender`、用户原话 `quote` 及 `active`。线程内可明确排除此发件人，也支持“以后不用回这个地址”。撤销规则后，尚未清理或删除的排除项恢复判断；丢弃或清理项不会复活。

## 拟稿与逐封发送

聊天、主动草稿要求和自动分类共用现有一个 Agent 执行器。聊天先执行，主动草稿要求优先于后台整理和分类。已经开始的模型请求无法立即抢占，邮件拟稿请求上限 60 秒。同步独立运行，不等待模型。

分类显示无需回复、可能需要回复、已拟稿或待补充。用户可主动请求草稿、修改、标记这封不用回或设置排除规则。草稿只在 Hikari 保存，手机和电脑编辑同一份。

最终编辑页展示收件人、抄送、主题、纯文本正文、发送附件和待补充问题。默认回复发件人；回复全部、其他收件人、抄送及附件由用户选择。来信附件不会自动附回。手工编辑不会被后台 AI 覆盖；有新来信时保留旧稿并提示复核，新来信等待用户主动要求更新。

“确认并发送此版本”只有在修改保存、正文非空、待补充问题清空后可用。用户在完整编辑页点击一次即确认，不增加第二个确认弹窗。服务器再次同步核对线程与外部回复，版本变化则拒绝旧确认。冻结版本包含收件人、抄送、主题、正文与附件标识、名称和内容哈希；发送附件变化会阻止发送。

本次开发仅使用模拟发送。真实邮件仍须由用户本人逐封打开完整编辑页并确认，开发者或 AI 不得代点真实邮件的发送按钮。

## 发送异常

- 收到 SMTP 的明确接受后显示已发送；不代表对方收到或已读。
- 明确在服务器接受之前失败，保留草稿。相同版本和请求只查询原发送记录；修正问题、重新保存为新版本，再由用户确认重试。
- DATA 提交后连接中断、进程在提交期间退出等情况显示“发送结果待核实”。不会自动重发，重启也不会重放。
- 后续在已发送文件夹发现本次生成的 Message-ID 时可核实成功。该文件夹暂时未找到邮件不能认定失败。用户可检查邮箱后明确标为已发送。
- 如果一直无法核实，用户可明确承担重复发送风险，回到复核状态；仍须保存并在完整编辑页确认新版本。
- SMTP 与本地 SQLite 无法组成跨服务器事务，不宣称远端恰好发送一次。同步后的极短远端变化窗口也无法通过本地事务彻底消除。

## 附件、清理与备份

来信附件保存在邮件区域，不进入学习资料库。自动读取 PDF、DOCX、PPTX、UTF-8 文本与 Markdown 的文字；图片、扫描、解析失败和超限内容明确标为未完整读懂，形成待补充问题。用户核对其是否影响回复后，再补齐正文并删除已解决的问题。当前没有自动图片识别。

处理上限：单封邮件 30 MB、单个附件 20 MB、附件提取文字 60,000 字符、邮件正文 100,000 字符、单次模型上下文 180,000 字符。超过邮件大小上限仅保留邮件头与警告，不阻塞其余邮件同步；过长上下文进入可能需要回复，允许手工编辑。Office 格式复用现有解压大小检查。限制或失败不应被理解为已完整阅读。

“清理本地内容”删除正文、来信附件、发送附件、草稿和草稿旧版本，保留处理标识、线程关联和必要发送状态。无需先放弃待确认或待补充草稿。其他内容立即清理；正在提交的冻结内容待操作结束后清理，若期间重启，先转为待核实再清理。清理不能撤回邮件，不影响服务器邮件，不重新拟稿同一封邮件。主动重新获取或同线程新来信可以继续处理。

本地清理属于应用数据清理，不承诺操作系统、存储设备、云同步或外部备份上的取证级擦除。SQLite 清理操作启用 secure_delete；已有备份单独保留。

学习空间备份现在包含邮件数据库内容、附件、草稿、发送记录和两个 Markdown 文件；不包含邮箱凭证文件。备份界面明确提示私人邮件内容，旧备份可在“管理旧备份”逐个删除，包括 ZIP 备份与旧资料清理脚本生成的 `.sqlite3` 快照。恢复必须停服，恢复数据库及 `email`、`memory`、`generated`，保留恢复前副本；邮箱凭证需要当前 Windows 用户重新配置。备份中的未决提交启动后仍进入待核实。

“暂停自动拟稿”继续同步；“断开邮箱”停止收发、等待已提交操作结束并删除本机凭证，保留记录。邮箱端客户端密码的撤销仍由用户在邮箱网页操作。

## 验证与仍待接入的事项

自动测试全部使用合成数据、模拟模型、IMAP 和 SMTP，没有真实云端邮件模型调用或真实邮件发送。验收覆盖需求文档的八组场景，包括重复同步与重启、跨设备与线程版本冲突、最终正文和附件一致、外部回复、发送结果不明、规则重启与撤销、离线恢复和历史范围、清理去重及提交中恢复。

手机宽度与桌面宽度已在隔离页面检查：完整编辑、未保存时禁用发送、保存新版本、一次点击模拟发送、完成后冻结字段。见 [手机宽度截图](images/email-mobile-demo.jpg) 和 [桌面截图](images/email-desktop-demo.jpg)。这不等于 Android 真机或真实邮箱验收。

真实接入后仍须验证：账户 IMAP/SMTP 开通与认证、实际已发送文件夹名、文件夹编码与连接限制、服务器 UID 变化、无标准线程头的往来、SMTP 是否保存已发送副本和是否保留 Message-ID、真实附件提取质量、云端模型分类与拟稿质量及用量、手机实际操作。任何真实发送都由用户逐封确认。

复现模拟界面：`python scripts/preview_email.py`，本机端口 8767，预览账户 `preview`、密码 `local-preview-only`。此脚本每次建立独立的 `.test-data-email-preview-*` 目录，只使用模拟收发，不读取正式数据或凭证；检查后停止该预览进程即可。
